# Adaptive Chess

Настольные шахматы для Windows 10/11 x64: соперник подстраивается под качество вашей игры
и стремится быть немного сильнее. Оффлайн, без аккаунтов, серверов и подписок.

## Готовая версия

В [Releases](https://github.com/oldsew/chess/releases) скачайте `AdaptiveChess-Windows-x64.zip`,
распакуйте **весь** архив и откройте `AdaptiveChess/AdaptiveChess.exe` двойным щелчком.
Не переносите один exe отдельно от `_internal`. Установка Python, Qt и Stockfish не нужна.
`SHA256SUMS.txt` содержит контрольные суммы; проверка в PowerShell:

```powershell
Get-FileHash .\AdaptiveChess-Windows-x64.zip -Algorithm SHA256
```

Пока релиз не опубликован, результат каждого успешного Windows CI находится в разделе
[Actions](https://github.com/oldsew/chess/actions/workflows/windows-release.yml).
Исходники: репозиторий и `AdaptiveChess_Source.zip` в release artifact.

## Игра

Выберите цвет и контроль времени, затем нажмите «Новая партия». Доступны «Без времени»,
30+0, 15+10, 10+5, 5+3, 3+2 и 1+0. Числа означают начальные минуты и секунды добавления
после каждого хода. Последний выбранный контроль запоминается. Часы активной стороны выделены;
они используют монотонное время и продолжают идти при просмотре предыдущих ходов.
При падении флага партия завершается по времени; если соперник не имеет материала для мата,
фиксируется ничья. Адаптивный уровень пока единый для всех контролей.

Ходите щелчками по фигуре и клетке либо перетаскиванием. Повторный щелчок по выбранной
фигуре полностью снимает выбор. При превращении выберите фигуру.
Шах, последний ход и допустимые клетки мягко подсвечиваются. Над списком ходов показан
устойчивый текстовый индикатор преимущества с вашей точки зрения, включая игру чёрными.
Точные оценки скрыты до включения Developer Mode.
Фигуры перемещаются за 250 мс с OutCubic без блокировки UI; взятие плавно исчезает,
рокировка двигает короля и ладью одновременно, превращение завершается мягкой сменой фигуры.
После перетаскивания фигура доводится от указателя до центра клетки, не повторяя весь ход.
Векторные ivory/graphite-фигуры используют градиенты и мягкие тени без настоящего 3D.
Набор имеет единый точёный пьедестал, плавные силуэты и сдержанные блики.
Над и под доской показаны потерянные фигуры (ферзь, ладьи, слоны, кони, пешки)
и материальный баланс с вашей стороны. Это отдельная визуальная информация: она не меняет
силу движка или live-индикатор. Потери восстанавливаются по взятиям из истории, включая en passant
и превращённые фигуры; при просмотре ходов они соответствуют просматриваемому моменту.
В настройках «Звуки игры» включают короткие встроенные сигналы хода, взятия, шаха и окончания
партии. Системный beep не используется. Без доступного аудиоустройства игра работает молча.
Рокировка, en passant, мат, пат и недостаток материала обрабатываются python-chess.
При доступном требовании ничьей по трёхкратному повторению/50 ходам приложение автоматически
фиксирует ничью (в том числе когда её можно потребовать объявлением следующего хода).
Можно сдаться. Согласованная ничья с компьютером не предусмотрена.
После матующего хода клетка проигравшего короля мягко пульсирует 650 мс, затем открывается
результат и существующий анализ. Настройка «Анимации» и системное отключение анимаций Windows
упрощают этот эффект.

После каждого полухода партия сохраняется. «Продолжить» восстанавливает последнюю незавершённую
партию вместе с историей ходов, контролем и оставшимся временем. При закрытом приложении
часы стоят на паузе; дополнительно они сохраняются каждые две секунды. Старые базы автоматически
получают новые поля без удаления партий и сброса рейтинга.

Кнопки ← / → и выбор полухода в списке показывают предыдущие позиции, не отменяя ходов.
Стрелки клавиатуры работают, когда фокус на доске. В режиме «Просмотр партии» нельзя ходить
или сдаваться; индикатор текущей позиции временно скрыт. «К текущей позиции» возвращает
самую свежую позицию, даже если компьютер уже ответил. PGN и реальные часы не откатываются.
История партий показывает контроль времени и причину завершения.

Можно закрыть приложение во время размышления или анализа:
последний завершённый ход сохранён; незавершённый анализ возобновляется при запуске.
После партии доступны результат, оценка уровня, точность и разбор каждого вашего хода.
Двойной щелчок по завершённой партии в истории открывает разбор; выбор строки разбора
показывает соответствующую позицию. Для неточностей и более серьёзных ошибок добавляются
три лучших MultiPV-варианта (или все доступные, если legal moves меньше трёх), короткие линии
до шести полуходов, ответ соперника и блок «Совет». Нажмите на вариант и просмотрите его
стрелками; «К фактической партии» возвращает позицию после выбранного сыгранного хода.
Эта доска не меняет реальную партию, PGN или часы.

Советы полностью оффлайн. Матовые угрозы берутся из Stockfish; материальные причины указываются
только при согласованной оценке и изменении материала в проверенной легальной линии.
Формулировка относится к показанному варианту, а не обещает единственный ответ соперника.
Для непонятных причин используется нейтральный текст; безопасность короля и слабости пешек
не придумываются. Матовые переходы не показываются как обычная числовая потеря.
Обычный анализ хороших ходов, CPL/accuracy и атомарное применение рейтинга сохраняются.
Старые сохранённые разборы читаются; дополнительные варианты есть у новых анализов.
Статистика показывает результаты и график уровня.

Данные SQLite, настройки и `logs/app.log` сохраняются в пользовательском Qt AppDataLocation
(обычно `%APPDATA%/AdaptiveChess/AdaptiveChess`); каталог программы остаётся доступным только для чтения.
Для переноса данных копируйте всю папку пользовательских данных при закрытом приложении.
Повреждённые/отсутствующие настройки заменяются значениями по умолчанию. При ошибке базы
данные не удаляются автоматически; проверьте доступ или восстановите резервную копию.

## Адаптация

Начальный внутренний уровень — 1000. `player_rating` оценивает пользователя,
`target_bot_rating` задаёт желаемую силу, а `behavior_profile` управляет реальным выбором Stockfish.
Базовый отступ плавно растёт: около +40…+50 ниже 800, +50…+70 на 800–1000,
+70…+90 на 1000–1200, +90…+100 на 1200–1400 и +100 выше.
Например, сохранённый уровень 832 с прежним offset 100 получает следующую цель ≈885,
без переписывания уровня или прошлых партий. Сохранённый offset интерпретируется как поправка
относительно прежнего значения 100; эффективный отступ ограничен +20…+150. В расчёте участвуют результат, сила соперника, нелинейная точность,
средний CPL, ошибки и последние 10 партий с большим весом свежих. Максимальный шаг:
80 в первых 5 партиях, 50 до 15 партий, затем 25. Качественное поражение почти не снижает
уровень; плохая случайная победа даёт мало. Уже два тяжёлых поражения подряд уменьшают
поправку offset на 10; в такой серии снижение уровня ограничено 8 за партию.
Сдача без сыгранных ходов не создаёт свидетельств слабости.
Короткие партии имеют меньший вес.

Stockfish 17.1 анализирует до 20 MultiPV-кандидатов на слабых уровнях; ширина плавно уменьшается
до 8 на сильных. Профили интерполируют температуру, потолок CPL, склонность к спокойным ходам
и вероятности диапазонов 0–50 / 50–150 / 150–250 / выше 250 CPL.
Вероятности задают доли доступных диапазонов, а не дополнительный штраф уже маловероятным
ходам. Если разумного кандидата нужного диапазона нет, приложение не придумывает случайный зевок.
Skill Level остаётся 20 для надёжной оценки и не считается Elo. Слабость создаётся выбором
менее точных планов из более широкого набора. Мат в один обязателен, доказанный мат сохраняется,
проигрывающий мат избегается при наличии безопасного хода. Короткая проверка легальных
разменов запрещает очевидную отдачу ферзя и поддерживает очевидное выгодное взятие ферзя.
Параметры, пороги, бюджет MultiPV для ошибок и задержки вынесены в `app/config/tuning.json`.

Уровень **не является рейтингом FIDE/онлайн-сервиса**. Соответствие силы профилей абсолютному
Elo требует эмпирической калибровки. Очень низкие уровни могут оставаться сильнее ожидаемого:
приложение предпочитает правдоподобные ходы искусственным грубым зевкам. Субъективное
ощущение соперника нужно проверять длительными пользовательскими сессиями.

## Архитектура

- `app/services/game.py`: правила, состояние, PGN и результат.
- `app/services/engine.py`: сериализованный UCI, MultiPV, анализ, восстановление процесса.
- `app/services/session.py`: координация часов, автосохранения и обновления профиля.
- `app/services/clocks.py`: независимые от UI монотонные часы и расширяемые контроли.
- `app/services/live.py`: категории оценки с инверсией цвета и hysteresis.
- `app/services/material.py`: потери из фактических взятий и визуальный баланс.
- `app/services/coaching.py`: короткие легальные PV, матовые и материальные причины, безопасный fallback.
- `app/services/calibration.py`: локальные агрегаты поведения компьютера, отдельно от рейтинговой истории.
- `app/config/gameplay.json`: контроли, пороги 30/90/200 cp, запас 12 cp, live-лимит 80 мс
  и глубина 10, длительности анимаций и интервалы часов.
- `app/adaptive/`: вероятностный выбор, CPL/accuracy, рейтинг и скользящая история.
- `app/database/store.py`: SQLite/WAL, атомарное и идемпотентное применение анализа/рейтинга.
- `app/ui/`: PySide6-доска с SVG-фигурами, фоновые QRunnable, экраны и настройки.
- `resources/pieces/`: собственные объёмные SVG-фигуры, не зависящие от системных шрифтов.
- `resources/sounds/`: собственные короткие PCM WAV; воспроизведение через Qt Multimedia.
- `scripts/`: проверенная загрузка движка, нативная упаковка и smoke-проверка release.

Stockfish работает вне GUI-потока; один процесс и один worker исключают параллельные UCI-команды.
При закрытии задачи отменяются, процесс завершается. Пути определяются относительно ресурсов
PyInstaller; абсолютных путей разработчика нет.

## Сборка из исходников (Windows x64)

Нужен Python 3.12 x64 только на машине сборки, Git и доступ к официальным источникам пакетов.
Откройте PowerShell в корне проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements-dev.txt
.\.venv\Scripts\python scripts/fetch_stockfish.py --platform windows
$env:QT_QPA_PLATFORM = 'offscreen'
.\.venv\Scripts\python -m pytest -q
.\.venv\Scripts\python scripts/build_release.py
```

Результаты: `dist/AdaptiveChess/AdaptiveChess.exe`, `artifacts/AdaptiveChess-Windows-x64.zip`,
`AdaptiveChess_Source.zip`, `SHA256SUMS.txt` и отчёты `release-smoke/`. Сборка создаётся
на Windows: PyInstaller не кросс-компилирует Linux-сборки в Windows exe.
`git archive HEAD` включает в source zip **закоммиченные** исходники; перед release коммитите изменения.

GitHub Actions `.github/workflows/windows-release.yml` на `windows-latest` выполняет эти же шаги
при push в main и вручную. Тег `v*` дополнительно публикует release с готовыми архивами.
Для нового тега нужны права push; pipeline использует встроенный ограниченный `GITHUB_TOKEN`.
Smoke test запускает **упакованный exe** семь раз с отдельным каталогом данных, проверяя
настоящее окно Qt, ввод по доске, несколько ответов Stockfish, автосохранение, настройки,
выход, продолжение, анализ завершённой партии, обновление рейтинга и следующего соперника.
Игровой smoke проверяет все семь контролей и increment, запрет ходов из истории, часы при
просмотре, восстановление после паузы, реальный ответ Stockfish за белых при игре пользователя
чёрными, инверсию индикатора, матовую анимацию до результата, анализ и timeout. Для проверки
timeout в этом диагностическом режиме инъецируется монотонный источник времени; первые
сценарии используют реальные часы, закрытие и повторный запуск exe.
Отдельный UX smoke проверяет промежуточные кадры семи анимаций, SVG, декодирование всех четырёх
WAV через Qt, маршрутизацию сигналов и отключение звука. На runner без аудиоустройства
отчёт явно отмечает отсутствие звукового выхода; слышимое воспроизведение на нём не проверяется.
Два learning-сценария дополнительно проверяют взятие, исторические потери, сохранение/перезапуск,
восстановление материала и диагностики, реальный слабый профиль для уровня 832, завершение
и оффлайн-разбор ошибки за белых и чёрных с тремя вариантами и советом. Проверяются просмотр
PV, возврат без изменения PGN и выборка 1000 решений слабого/сильного профиля с фиксированным seed.
Последняя выборка использует один заданный набор кандидатов и не сертифицирует абсолютный Elo.
Qt offscreen подходит для автоматизации, но не заменяет визуальный
ручной тест на конкретном компьютере Windows.

## Разработка в Linux

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python scripts/fetch_stockfish.py --platform linux
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -q
.venv/bin/python scripts/smoke_release.py
.venv/bin/python main.py  # при наличии графической сессии
```

Для Linux можно собрать нативный тестовый пакет тем же `scripts/build_release.py`.
Он не заменяет Windows release. Движок baseline x86-64 выбран для совместимости без AVX2.
`ADAPTIVE_CHESS_ENGINE` и `ADAPTIVE_CHESS_DATA_DIR` — необязательные локальные overrides.
Режим разработчика в настройках раскрывает профиль, кандидаты, вероятности, выбранный ход,
точную оценку со стороны белых и игрока, матовую оценку, категорию, пороги, hysteresis и live-глубину.
Также видны фактические MultiPV/глубина, CPL и вероятность каждого кандидата, ранги выбранных
ходов, средний/median CPL компьютера, распределение 0–25 / 25–50 / 50–100 / 100–150 / 150–250 / >250,
число ошибок и частота нахождения единственного существенно лучшего хода.
Файлы `calibration/game-<id>.json` в пользовательской папке содержат локальные решения,
параметры, результат, accuracy и длительность для будущей калибровки. Никакие данные не отправляются
на сервер; повреждение необязательного файла диагностики не препятствует игре.

## Ограничения MVP

- Анализ: глубина 16 по умолчанию (12…22), с лимитом 0,35 с на позицию для отзывчивости;
  фактическая глубина может быть ниже. Матовые оценки сохраняются отдельно в формате `#N`;
  CPL для матов использует насыщение ±100000, а не обычную пешечную оценку.
- Accuracy — собственная нелинейная метрика; не воспроизводит коммерческие сайты.
- Нет онлайн-игры, произвольного контроля в UI, согласованной ничьей и внешнего AI-тренера. Обучающие советы ограничены проверенными матовыми/материальными фактами.
- Неподписанный Windows exe может вызвать SmartScreen. Проверьте происхождение и SHA256.
- Никакая успешная Linux-проверка сама по себе не доказывает работоспособность Windows exe;
  статус Windows CI и его smoke-отчёты являются отдельным подтверждением.
